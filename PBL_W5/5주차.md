# 📘 Today I Learned
### 1. 오늘 배운 내용
- 레이어드 아키텍처 : 시스템을 Repository(데이터), Service(비즈니스 로직), Main(실행/조립) 계층으로 분리하여 관리하는 방법을 학습했습니다.
- 강한 결합의 문제점: 클래스 내부에서 다른 객체를 직접 생성(new)하면, 의존하는 객체가 바뀔 때마다 내부 코드를 수정해야 하는 유연성 저하 문제를 확인했습니다.
- 의존성 주입 : 객체를 직접 생성하지 않고 외부(Main)에서 생성자를 통해 넣어줌으로써 클래스 간의 결합도를 낮추는 설계를 실습했습니다.
- 제어의 역전 : 객체의 생성 및 생명주기 관리 권한이 서비스 자신이 아닌 외부(프레임워크나 Main)로 넘어가는 개념을 이해했습니다.

### 2. 핵심 정리 (내 언어로)
- 인터페이스는 '약속'입니다.
- MemberService는 구체적으로 어떤 저장소(Memory인지 Mock인지)를 쓰는지 몰라도 됩니다.
- 단지 MemberRepository라는 인터페이스가 정해준 규칙(메서드)만 믿고 호출하면 됩니다.
- DI는 '조립'입니다.
- 레고 블록처럼 Main에서 원하는 부품(구현체)을 골라 Service라는 본체에 끼워 넣는 것과 같습니다.
- 덕분에 본체 코드를 뜯어고치지 않고도 부품만 갈아 끼워 기능을 바꿀 수 있습니다.

### 4. 느낀 점
- 처음에는 인터페이스를 만들고 생성자를 따로 작성하는 과정이 번거롭게 느껴졌지만, 실제로 Main에서 코드 한 줄만 바꿔서 가짜 데이터(Mock)와 실제 저장소(Memory)를 자유자재로 오가는 것을 보니 왜 이런 구조가 필요한지 확실히 체감할 수 있었습니다.
- 특히 Scanner 입력 시 데이터 타입을 맞추지 않으면 InputMismatchException이 발생한다는 점을 통해 예외 처리와 사용자 입력 순서 설계의 중요성도 다시 한번 배웠습니다.
- 이 구조가 나중에 배울 Spring 프레임워크의 핵심 기반이 된다고 하니, 객체지향 설계 원칙을 더 깊이 공부해야겠다는 동기부여가 되었습니다.
