# 🗒️ Today I Learned

### 1. 오늘 배운 내용
- 전역 예외 처리(@RestControllerAdvice)를 도입하여 에러 처리를 한 곳으로 모으는 방법
- 커스텀 예외 클래스(RuntimeException 상속)를 만들어서 비즈니스 예외를 표현하는 방법
- Service에서 null을 반환하는 대신 예외를 던지고, Controller는 정상 흐름만 담당하도록 리팩토링하는 방법
- Spring Data JPA의 쿼리 메서드 네이밍 규칙(existsByName, findByPart, findByTitleContaining)으로 검색 기능을 구현하는 방법
- 프론트엔드에서 fetch()로 백엔드 API를 호출하고, JSON 응답을 받아 화면에 렌더링하는 흐름

### 2. 핵심 정리 (내 언어로)
이번 주차에서 가장 크게 느낀 건 "각 계층의 책임을 분리하는 것"의 중요성이었습니다.
기존에는 Controller에서 null 체크를 하고 에러 응답을 직접 만들었는데, 이렇게 하면 같은 에러 처리 코드가 여러 메서드에 반복됩니다.
이번에 @RestControllerAdvice를 도입하면서 Controller는 정상 흐름만 담당하고, 에러는 GlobalExceptionHandler가 한 곳에서 처리하도록 바꿨습니다.
코드가 훨씬 깔끔해지고 에러 응답 형식도 통일됐습니다.

또한 Service에서 null을 반환하는 것보다 예외를 던지는 게 더 안전하다는 걸 배웠습니다.
null을 반환하면 호출하는 쪽에서 매번 null 체크를 해야 하지만, 예외를 던지면 전역 예외 처리기가 알아서 잡아주기 때문입니다.

프론트엔드 연동을 통해 실제로 버튼을 누르면 fetch()가 백엔드 API를 호출하고, JSON 응답을 받아 화면에 표시되는 전체 흐름을 직접 눈으로 확인할 수 있었습니다.
