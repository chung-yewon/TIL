# 📘 Today I Learned

### 1. 오늘 배운 내용
- JPA(Java Persistence API)를 사용해서 데이터를 MySQL 데이터베이스에 영구적으로 저장하는 구조로 전환했습니다.
- `@Entity` 어노테이션으로 Java 클래스를 DB 테이블과 매핑하는 방법을 배웠습니다.
- `@Id`, `@GeneratedValue(strategy = GenerationType.IDENTITY)`로 DB가 자동으로 기본키(id)를 생성하게 했습니다.
- `@Enumerated(EnumType.STRING)`으로 Enum 값을 DB에 문자열(LION, STAFF)로 저장했습니다.
- `JpaRepository`를 상속하면 `save()`, `findById()`, `findAll()`, `deleteById()` 등의 메서드가 자동으로 제공된다는 것을 배웠습니다.
- 7주차에서 상속 구조(Role → Lion/Staff)로 구현했던 것을 단일 `Member` 엔티티 + `RoleType` Enum으로 간소화했습니다.
- Hibernate가 콘솔에 자동으로 SQL을 출력해주는 것을 확인했습니다.

### 2. 핵심 정리 (내 언어로)
JPA를 쓰기 전에는 데이터를 ArrayList(메모리)에 저장했기 때문에 서버를 재시작하면 모든 데이터가 사라졌습니다.
JPA를 도입하면 Java 객체와 DB 테이블을 자동으로 연결해주기 때문에 SQL을 직접 작성하지 않아도 데이터를 저장, 조회, 수정, 삭제할 수 있습니다.
특히 `save()` 메서드를 호출하면 영속성 컨텍스트를 통해 DB에 INSERT가 실행되고, 그 반환값에는 DB가 자동으로 채워준 `id` 값이 담겨 있습니다.
이 덕분에 등록 직후 응답에 `id`를 포함할 수 있었습니다.
또한 7주차에서 Lion과 Staff를 별도 클래스로 관리했던 것을, 이번엔 `RoleType`이라는 Enum 하나로 구분하게 되었습니다.
관계형 DB에는 '상속' 개념이 없기 때문에 Enum + 단일 테이블로 처리하는 것이 더 실용적이라는 것을 배웠습니다.

### 4. 느낀 점
처음에 JPA가 SQL을 자동으로 만들어준다는 게 잘 이해되지 않았는데, 실제로 콘솔에 Hibernate SQL이 출력되는 것을 보고 나서야 제가 `save()`를 호출하면 JPA가 알아서 INSERT 쿼리를 실행해준다는 것을 이해했습니다.
또 MySQL Workbench에서 직접 테이블을 확인했을 때 데이터가 실제로 저장되어 있는 것을 보니 신기하고 뿌듯했습니다.
앞으로 연관관계와 트랜잭션도 배울 예정인데, JPA의 기초를 이번에 잘 다진 것 같아서 기대가 됩니다.
