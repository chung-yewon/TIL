# 📘 Today I Learned

### 1. 오늘 배운 내용
- Spring Boot 프로젝트 환경 구축 및 코드 이식 : Java 17, Spring Boot 3.x 환경에서 제약 사항에 맞춰 `config`, `controller`, `domain`, `repository`, `service` 패키지로 계층 구조를 분리하고 5주 차 순수 자바 코드를 이전했습니다.
- 수동 의존성 주입(DI) : 설정 클래스(`AppConfig`)를 생성하여 `@Configuration`과 `@Bean` 어노테이션을 통해 스프링 컨테이너에 객체를 직접 등록하고 조립하는 방법을 학습했습니다.
- 자동 의존성 주입 전환 : `@Component` 기반의 `@Service`, `@Repository` 어노테이션을 구현체 클래스에 부여하여 스프링의 컴포넌트 스캔 기능으로 Bean을 자동 등록했습니다.
- 첫 REST API 구현 : `@RestController`와 `@GetMapping`을 활용해 웹 브라우저의 HTTP 요청을 받아 처리하는 간단한 API 작성법을 익혔습니다.

### 2. 핵심 정리 (내 언어로)
- IoC/DI의 주도권 변화 : 5주 차에는 개발자가 직접 `new`로 객체를 만들고 조립했지만, 스프링 부트에서는 스프링 컨테이너(ApplicationContext)라는 바구니가 객체의 생성과 연결을 대신 처리해 줍니다. 개발자의 개입이 줄어들면서 결합도가 낮고 관리가 쉬운 코드가 됩니다.
- 생성자 주입의 편리함 : 클래스 내에 생성자가 단 1개만 존재할 때는 스프링이 무조건 그 생성자를 사용해 의존성을 주입하므로, 굳이 `@Autowired`를 붙이지 않아도 자동으로 연결됩니다.
- 자바의 패키지 매커니즘 : 자바에서는 클래스 이름이 완전히 같더라도 소속된 패키지(폴더 경로)가 다르면 완전히 다른 객체로 취급된다. 다른 패키지의 클래스를 가져다 쓸 때는 상단에 `import` 경로를 정확히 맞춰주는 과정이 필수적입니다.

### 4. 느낀 점
- 순수 자바 코드를 스프링 패키지 안으로 옮길 때 패키지 경로 꼬임으로 에러가 대량 발생하여 당황했으나, 인텔리제이의 디버깅 가이드와 `import` 메커니즘을 하나씩 해결해 가며 빌드를 정상화했을 때 큰 성취감을 느꼈습니다.
- 이론으로만 듣던 제어의 역전(IoC)을 수동 설정(`AppConfig`)에서 자동 설정(`@Service`, `@Repository`)으로 직접 전환해 보면서 코드가 한결 깔끔해지고 스프링이 왜 강력한 프레임워크인지 체감할 수 있었습니다.
- 다음 주차부터는 데이터 저장소 계층(`repository`)에 영속성 컨텍스트(JPA)를 적용해 실제 DB에 저장하는 과정을 배운다고 하니, 이번에 잡아놓은 인터페이스와 구현체 분리 개념을 단단히 복습해 두어야겠다고 생각했습니다.
